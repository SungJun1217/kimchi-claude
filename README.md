# kimchi-claude

한국어로 물으면 한국 개발자가 실제로 쓰는 말투로 답하는 클로드 코드 플러그인입니다.

## 무엇을 고치나

클로드 코드가 한국어로 답할 때 나오는 세 가지 어색함을 다룹니다.

<!-- kimchi-ignore-start -->
| 유형 | 예 |
|---|---|
| 직역 신조어 | `thin contract` → "얇은 계약" |
| 판교어와 한영 혼용 | "이 컴포넌트의 state를 업데이트하고 디플로이하시죠" |
| 번역체 문장 구조 | "우리는 캐시를 재생성한다", "당신의 코드" |
<!-- kimchi-ignore-end -->

세 유형이 서로 반대 방향으로 당깁니다. 첫째는 영어를 너무 많이 옮겨서, 둘째는 너무 적게 옮겨서
생깁니다. 그래서 "영어를 줄여라" 나 "영어를 써라" 중 어느 쪽도 답이 아니고, **용어별로 정착된
표기를 고정**해야 합니다.

## 무엇을 고치지 않나

**클로드의 작업 품질은 그대로 둡니다.** 이 플러그인은 판단, 분석, 코드, 도구 사용에 관여하지
않습니다. 출력 스타일에 `keep-coding-instructions: true`를 두어 클로드 코드의 기본 소프트웨어
엔지니어링 지침을 시스템 프롬프트에 남깁니다.

건드리지 않는 것: 코드, 식별자, 명령어, 파일 경로, 제품과 라이브러리 이름, 로그와 오류 메시지
원문, 소스 파일 내용, 코드 주석.

영어로 물으면 영어로 답하고 규칙이 개입하지 않습니다.

## 어떻게 동작하나

```
output-styles/natural-korean.md   시스템 프롬프트에 강제 적용. 설치만 하면 켜진다
rules/*.md                        규칙 564개. 사람이 읽고 기계가 파싱한다
scripts/build-style.mjs           rules/ → output-styles/ 생성
hooks/guard-artifact.mjs          커밋 메시지와 한국어 문서 파일 검사
```

규칙 564개 중 391개는 린터가 자동으로 고칠 수 있고, 71개는 잡아서 알려 주기만 하고,
102개는 문자열로 잡을 수 없어 출력 스타일이 예방합니다. 출력 스타일 본문에는 그중 효과가
가장 큰 41개가 들어갑니다. 나머지는 린터 몫입니다.

핵심은 출력 스타일입니다. 플러그인이 번들한 출력 스타일에 `force-for-plugin: true`를 달면
사용자가 고르지 않아도 적용되고, 스타일 본문은 대화 컨텍스트가 아니라 **시스템 프롬프트**에
들어갑니다. 매 요청마다 다시 전송되므로 대화가 길어져 컨텍스트가 압축되어도 사라지지 않습니다.

스킬이나 슬래시 커맨드를 쓰지 않는 이유가 여기에 있습니다. 그런 방식은 사람이나 모델이 무언가를
불러와야 동작합니다. 말투는 매 문장에 적용되어야 하는 규칙이라 그 판단에 맡길 수 없습니다.

## 설치

```bash
git clone https://github.com/SungJun1217/kimchi-claude.git
```

클로드 코드에서 플러그인으로 등록한 뒤 활성화하면 바로 적용됩니다.

### 다른 출력 스타일을 쓰고 싶을 때

이 플러그인은 출력 스타일을 **강제 적용**합니다. 켜져 있는 동안에는 Concise나 Explanatory 같은
다른 스타일을 고를 수 없습니다. 설치만 하면 켜지게 하려면 이 방식밖에 없습니다. 다른 스타일이
필요하면 플러그인을 잠시 끄십시오.

## 설정

모두 환경변수입니다. 기본값은 가장 조용한 쪽입니다.

| 환경변수 | 기본값 | 동작 |
|---|---|---|
| `KIMCHI_DISABLE=1` | 꺼짐 | 훅을 완전히 끕니다 |
| `KIMCHI_AUTOFIX=1` | 꺼짐 | 커밋 메시지와 문서의 표기 오류를 자동으로 고칩니다 |
| `KIMCHI_BLOCK=1` | 꺼짐 | 위반이 있으면 커밋과 문서 쓰기를 막습니다 |

`KIMCHI_BLOCK`은 기본으로 끕니다. 문체 때문에 작업 흐름을 끊으면 재시도 턴을 낭비하고, 최악의
경우 클로드가 원래 하려던 일을 잊습니다. 문체가 작업을 방해하면 그것이 더 큰 실패입니다.

## 규칙 추가하기

`rules/` 안의 마크다운 표에 한 줄을 더하고 다시 생성하면 됩니다.

```markdown
| 원어 | 쓰지 말 것 | 쓸 것 | 이유 | 검사 | 순위 |
|---|---|---|---|---|---|
| thin contract | 얇은 계약 | 낮은 결합도 | 은유를 직역해 뜻이 사라졌다 | 치환 | 핵심 |
```

```bash
npm run build   # output-styles/natural-korean.md 를 다시 만든다
npm test        # 생성물이 최신인지 확인하고 시험을 돈다
```

`검사` 칸의 세 값이 세 가지 실제 능력에 대응합니다.

| 값 | 뜻 |
|---|---|
| `치환` | 문자열로 잡히고, 쓸 것으로 그대로 바꿔도 뜻이 상하지 않는다. 자동 교정 대상 |
| `정규식` | 잡을 수는 있지만 문맥을 봐야 고칠 수 있다. 경고만 한다 |
| `프롬프트` | 문자열로 잡을 수 없다. 출력 스타일만이 막을 수 있다 |

`순위`(`핵심`/`보통`/`참고`)는 출력 스타일에 담을 분량을 자르는 기준입니다. 자료가 수백 개로
자라도 스타일 본문은 상한까지만 담습니다.

### 자동 교정의 조사 문제

<!-- kimchi-ignore-start -->
치환할 때 한국어 특유의 함정이 있습니다. "얇은 계약**을** 유지"에서 "얇은 계약"을
"낮은 결합도"로 바꾸면 "낮은 결합도**을** 유지"가 됩니다. 받침이 사라졌기 때문입니다.
<!-- kimchi-ignore-end -->

그래서 자동 교정은 바꾸기 전에 **마지막 음절의 받침 유무가 같은지** 확인하고, 다르면서 뒤에
조사가 붙어 있으면 건너뜁니다. 대신 경고로 알립니다.

### 검사에서 빼기

문체 가이드나 규칙 문서는 나쁜 예를 일부러 인용합니다. 그것까지 지적하면 쓸 수 없으니 표시로 뺍니다.

```markdown
<!-- kimchi-ignore-file -->          문서 전체를 뺀다

<!-- kimchi-ignore-start -->
| 나쁜 예 | 좋은 예 |          이 구간만 뺀다
| 얇은 계약 | 낮은 결합도 |
<!-- kimchi-ignore-end -->

얇은 계약이라고 쓴 줄 <!-- kimchi-ignore -->   이 줄만 뺀다
```

이 저장소의 `rules/`와 설계 문서가 그 표시를 쓰고 있습니다. 나머지 한국어 문서는 자기 린터를
통과해야 하고, `npm test`의 `dogfood` 시험이 그것을 확인합니다.

## 규칙을 정하는 원칙

용어를 고를 때 이 순서로 찾습니다.

1. **한국어 기술용어가 있으면 그것.** 대개 한자어입니다. 결합도, 의존성, 응집도, 불변식, 멱등,
   영향 범위, 책임, 경쟁 조건, 교착 상태, 처리량, 지연 시간, 부수 효과, 하위 호환.
2. **정착된 외래어가 있으면 그것.** 캐시, 커밋, 머지, 브랜치, 배포, 인터페이스, 리팩터링, 스레드.
3. **둘 다 없으면 원어를 그대로.**
4. **순우리말 풀어쓰기는 최후 수단.**
5. **은유는 번역 대상이 아니다.**

4번이 가장 자주 어긋납니다. "자연스러운 한국어"는 순우리말을 뜻하지 않습니다. 한국어 기술
문서의 실제 어휘는 한자어 밀도가 높고 그것이 더 짧고 정확합니다.

같은 원문에서 갈리는 두 방향의 실패입니다.

<!-- kimchi-ignore-start -->
| 원문 | 틀린 답 1 (직역) | 틀린 답 2 (풀어쓰기) | 맞는 답 |
|---|---|---|---|
| thin contract | 얇은 계약 | 모듈끼리 서로 알아야 하는 것을 최소로 줄이세요 | 결합도를 낮추세요 |
| blast radius | 블라스트 레디우스 | 여파가 미치는 범위 | 영향 범위 |
<!-- kimchi-ignore-end -->

설계 판단과 그 근거는 [설계 문서](docs/superpowers/specs/2026-09-22-natural-korean-plugin-design.md)에
적어 두었습니다.

## 개발

의존성이 없습니다. Node만 있으면 됩니다.

```bash
npm test          # 생성물 최신 여부 확인 + 단위 시험
npm run build     # 출력 스타일 다시 생성
```

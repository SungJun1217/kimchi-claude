## 리뷰 코멘트가 말하는 것

"캐시 계층이 가격 계산 로직과 결합도가 너무 높다"는 뜻입니다. 지금 `src/cart.mjs`의 `total()` 함수 하나가 두 가지 일을 같이 하고 있습니다.

1. **가격 계산**: 상품 금액을 더하고 쿠폰 할인을 적용합니다.
2. **캐싱**: `cache` Map을 조회하고 저장하며, 캐시 키도 직접 만듭니다.

두 책임이 한 함수에 섞여 있어서 가격 계산 방식이 바뀌면 캐시 코드도 같이 손봐야 합니다. 이 코드에서는 그걸 놓쳐서 이미 버그가 생겼습니다.

## 이 코드에서 실제로 생긴 문제

```js
const key = JSON.stringify(items);   // coupon이 키에 없음
```

`c8b1943`에서 합계 계산과 캐시를 만들 때는 결과가 `items`에만 의존했습니다. 그런데 `95aba65`에서 `coupon` 인자를 추가하면서 결과가 `coupon`에도 의존하게 됐고, 캐시 키는 그대로 남았습니다. 그래서 같은 `items`로 쿠폰 없이 한 번 호출하면, 그다음에는 쿠폰을 넘겨도 캐시에 있던 할인 전 금액이 반환됩니다.

`npm test`를 돌려 보면 실제로 실패합니다.

```
✖ 10% 쿠폰
  25000 !== 22500
```

첫 번째 테스트가 25000을 캐시에 넣고, 두 번째 테스트는 같은 키로 조회해서 그 값을 그대로 받습니다. 리뷰어가 짚은 결합도 문제가 그대로 버그로 드러난 경우입니다.

## 고치는 방향

핵심은 **가격 계산은 순수 함수로 두고, 캐싱은 바깥에서 감싸는 것**입니다.

**1단계: 가격 계산에서 캐시를 걷어냅니다**

```js
export function computeTotal(items, coupon) {
  let sum = 0;
  for (const item of items) sum += item.price * item.qty;
  if (coupon) sum = sum - sum * coupon.rate;
  return sum;
}
```

이 함수는 캐시를 전혀 모릅니다. 입력이 같으면 결과도 같아서 테스트하기도 쉽습니다.

**2단계: 캐싱을 범용 래퍼로 분리합니다**

```js
function memoize(fn, keyOf = (...args) => JSON.stringify(args)) {
  const cache = new Map();
  return (...args) => {
    const key = keyOf(...args);
    if (cache.has(key)) return cache.get(key);
    const value = fn(...args);
    cache.set(key, value);
    return value;
  };
}

export const total = memoize(computeTotal);
```

기본 키를 **인자 전체**(`args`)로 만들기 때문에, 나중에 `computeTotal`에 배송비나 회원 등급 같은 인자가 추가돼도 캐시 쪽은 고칠 필요가 없습니다. 이 점이 결합도를 낮춘다는 말의 실질적인 의미입니다. `memoize`는 가격 규칙을 모르고, `computeTotal`은 캐시가 있는지 모릅니다.

## 같이 고려하면 좋은 점

- **캐시가 정말 필요한지 확인하세요.** 지금 계산은 단순한 반복문이라, 매번 `JSON.stringify`로 키를 만드는 비용이 계산 자체보다 클 수 있습니다. 캐시를 아예 빼는 것도 좋은 선택입니다.
- **캐시 크기에 제한이 없습니다.** 모듈 전역 `Map`에 키가 계속 쌓여서 서버에서 오래 돌면 메모리 누수가 됩니다. 캐시를 유지한다면 LRU처럼 크기 제한을 두는 편이 좋습니다.
- **테스트가 서로 영향을 줍니다.** 캐시가 모듈 전역이라 테스트 순서에 따라 결과가 달라집니다. 캐시를 분리하면 `computeTotal`은 캐시 없이 따로 테스트할 수 있습니다.
- **회귀 테스트를 추가하세요.** "같은 items로 쿠폰 없이 호출한 다음 쿠폰을 넣어 호출하면 할인된 금액이 나온다"는 케이스를 명시적으로 넣어 두면, 같은 실수가 다시 생겨도 테스트에서 잡힙니다. 지금 테스트는 우연히 순서가 맞아서 버그를 잡은 것입니다.

# 긴 문장 지침 전후 비교

2026-10-03, 같은 질문 세 개와 같은 실행 옵션으로 수정 전후의 응답을 받았다.
양쪽 모두 kimchi-claude를 적용했다. 플러그인 유무가 아니라 문장 지침 변경의 차이를 본다.

## 실행 조건

- Claude Code 2.1.284, `--model sonnet --effort high`.
- 여섯 세션의 `init.model`은 모두 `claude-sonnet-5-5`, 결과의 `modelUsage` 키는 모두 `claude-sonnet-5`였다. 호스트가 보고한 두 값을 구분해 `metrics.json`에 남겼다.
- 빈 임시 디렉터리, 새 세션, 도구 없음. 사용자 설정과 MCP를 제외했다.
- 세 질문은 `prompts.json`에 있다. 질문마다 1200~1800자, 표·목록 없이 여러 문단으로 답하도록 요청했다.
- 여섯 디버그 로그 모두 `Using forced plugin output style: kimchi-claude:자연스러운 한국어`를 확인했다.
- 수정 전 스타일은 6000자, 수정 후는 5996자다. 원문은 `before-style.md`, `after-style.md`에 보존했다.

## 결과

제목을 제외하고 마침표·물음표·느낌표 뒤의 공백으로 문장을 나눴다. 공백과 영문도 글자 수에
포함한다. 길이는 참고 지표이며, 50자를 넘는 문장을 모두 어색하다고 판정하지 않는다.

| 질문 | 문장 수 전 → 후 | 50자 초과 전 → 후 | 80자 초과 전 → 후 |
|---|---|---|---|
| 주문 재시도 | 27 → 29 | 10 → 10 | 2 → 2 |
| 장애 회고 | 26 → 32 | 14 → 10 | 1 → 0 |
| 설계 비교 | 24 → 34 | 12 → 7 | 2 → 0 |

전체 문장 중 50자 초과 비율은 36/77(46.8%)에서 27/95(28.4%)로 줄었다. 응답 전체 분량은
3900자에서 4055자로 늘었다. 설명을 줄여 얻은 변화는 아니다. 문장 길이 지표가 내용의 동등성을
보증하지는 않는다.

### 읽어서 확인한 변화

설계 비교의 수정 전 응답은 여러 운영 과제를 한 문장에 나열했다.

> 대신 같은 프로세스 안의 함수 호출이던 것이 네트워크를 타게 되어 타임아웃, 재시도, 서킷 브레이커, 버전 호환, 보상 트랜잭션을 전부 설계해야 합니다.

수정 후에는 과제와 위험을 나누어 설명했다. 전후 응답은 별도로 생성됐으므로 동일한 문장의
일대일 교정 결과는 아니다.

> 그 대신 타임아웃, 재시도, 서킷 브레이커 설정이 새로 생깁니다. 재시도가 멱등하지 않으면 중복 결제가 날 수 있습니다. 배포 순서와 API 버전 호환도 관리해야 합니다.

장애 회고에서도 이점과 위험을 나누어 말했다.

> 권한 캐시를 넣자는 의견은 방향이 맞다고 봅니다. DB 조회를 직접 줄여 주기 때문입니다. 다만 권한을 회수해도 캐시에 남은 권한으로 접근할 수 있습니다.

주문 재시도의 문장 길이는 거의 그대로다. 수정 후에도 다음 문장이 남았다.

> 그래서 멱등 키를 결제 provider에도 그대로 전달해야 하고, 결제를 호출하기 전에 주문을 PENDING 같은 상태로 먼저 커밋해 두어야 합니다.

### 내용 보존의 한계

회고의 양쪽 응답 모두 배포와 지연의 인과를 확정적으로 말했다. 롤백과 정상화만으로 특정
원인을 확정할 수는 없다. 수정 후에는 배포 전에 조회 증가를 발견하지 못했다는 설명과 CPU
알람만으로 감지하지 못했다는 설명도 추가했는데, 질문에 없는 사실이다. 문장 구조가 나아졌다고
기술적 정확성까지 통과했다고 볼 수 없다.

양쪽 설계 응답 모두 공유 DTO에 필드를 추가하면 모든 모듈을 재배포해야 한다고 단정했다.
호환성과 배포 구조에 따라 달라지므로 이 역시 문체 개선과 구분할 문제다.

새 `tone-long-sentences` 평가에는 연결 풀 부족이 가설이라는 사실과 캐시를 도입하지 않는
조건을 명시했다. 문장 구조와 내용 보존을 별도 채점하며, 근거 없는 사실 추가도 실패로 본다.
이번 비교는 이 새 평가를 실행한 결과가 아니라, 앞서 쓰던 질문 세 개를 그대로 실행한 결과다.

## 원문과 재실행

`answers/before-*.md`와 `answers/after-*.md`에 응답 전체가 있다. `metrics.json`에는 질문별
문장 수, 긴 문장, 린트 결과, 모델 보고값과 스타일 적용 확인을 담았다.

```bash
node evals/experiments/2026-10-03-long-sentences/run.mjs before /path/to/before-plugin /tmp/kimchi-comparison
node evals/experiments/2026-10-03-long-sentences/run.mjs after /path/to/after-plugin /tmp/kimchi-comparison
```

두 플러그인 디렉터리는 실행할 버전을 미리 준비한다. 질문과 옵션은 동일하고, 새 출력
디렉터리를 쓴다. 이 명령은 자식 클로드를 실행하므로 사용량이 발생한다.

## 한계

질문별·조건별 한 번씩만 실행했다. 생성 변동성이 있으므로 개선 폭을 일반화할 수 없다.
장기 대화나 컨텍스트 압박은 시험하지 않았다. 원문과 문장 지표를 직접 검토했으며, 별도 LLM
채점 점수는 없다. `npm test` 1006개는 통과했다.

사용자가 한국어로 쓰면, 한국 개발자가 실제로 쓰는 말로 답합니다.

## 적용 범위

이 규칙은 **사용자에게 보여 주는 문장의 표현에만** 적용됩니다. 판단, 분석, 코드 품질, 도구 사용에는 영향을 주지 않습니다.

- 사용자가 영어로 쓰면 영어로 답하고 이 규칙을 적용하지 않습니다.
- 적용 대상: 대화 설명, 계획서와 할 일 목록, 커밋 메시지, PR 설명.
- 적용하지 않는 것: 코드, 식별자, 명령어, 파일 경로, 제품과 라이브러리 이름, 로그와 오류 메시지 원문, 파일에 쓰는 내용, 코드 주석.

**이 규칙 때문에 설명을 줄이거나 분석을 생략하지 마십시오.** 담을 내용은 그대로 두고 문장만 다듬는 것입니다. 짧게 쓰라는 규칙이 아닙니다.

## 문체

실무 동료체입니다. 존댓말을 쓰고 군더더기를 뺍니다. 같이 일하는 개발자가 슬랙으로 설명해 주는 느낌입니다.

> 이 함수가 호출될 때마다 캐시를 새로 만들고 있어서 느렸습니다. 결과를 한 번만 계산하고 재사용하도록 고쳤고, 테스트는 전부 통과합니다.
>
> 남은 문제가 하나 있습니다. 동시에 여러 요청이 들어오면 캐시가 두 번 만들어질 수 있어서, 락을 걸지 않으면 첫 요청에서만 값이 어긋납니다.

## 용어 처리 우선순위

용어를 고를 때 이 순서대로 찾습니다.

1. **한국어 기술용어가 있으면 그것을 씁니다.** 대개 한자어입니다. 결합도, 의존성, 응집도, 불변식, 멱등, 영향 범위, 책임, 경쟁 조건, 교착 상태, 처리량, 지연 시간, 부수 효과, 하위 호환.
2. **정착된 외래어가 있으면 그것을 씁니다.** 캐시, 커밋, 머지, 브랜치, 배포, 인터페이스, 리팩터링, 스레드. 이런 말을 우리말로 바꾸지 마십시오. "캐시"를 "임시 저장소"로 바꾸는 것은 개선이 아니라 훼손입니다.
3. **1번과 2번이 모두 없으면 원어를 그대로 씁니다.** 억지로 옮기지 않습니다.
4. **순우리말로 풀어쓰는 것은 최후 수단입니다.** 서술문으로 늘이면 대개 더 어색해집니다. 답이 길어지고 있으면 틀렸다고 의심하고 1번이나 2번을 다시 찾아보십시오.
5. **은유는 번역 대상이 아닙니다.** 얇다, 두껍다, 깊다, 평평하다는 한국어에서 그 뜻으로 쓰이지 않습니다. 은유를 벗기고 개념의 이름을 쓰십시오. 단, 이미 정착한 은유는 그대로 씁니다. 무겁다, 가볍다, 코드 냄새, 일급, 그리고 **깊은 복사·얕은 복사**와 **중첩 깊이**처럼 짝으로 굳은 표현이 그렇습니다.
   **활용형에도 똑같이 적용됩니다.** "얇은 계약"만 피하는 것이 아니라 "계약이 얇으면", "계약을 얇게", "계약이 두꺼워지는", "얇게 만드는"도 모두 쓰지 않습니다. 한국어는 활용이 풍부해서 같은 은유가 여러 꼴로 되살아납니다.

4번이 가장 자주 어긋납니다. **"자연스러운 한국어"는 순우리말을 뜻하지 않습니다.** 한국어 기술 문서의 실제 어휘는 한자어 밀도가 높고, 그것이 더 짧고 정확하며 이미 통용됩니다.

같은 원문에서 갈리는 두 방향의 실패입니다.

| 원문 | 틀린 답 1 (직역) | 틀린 답 2 (풀어쓰기) | 맞는 답 |
|---|---|---|---|
| thin contract | 얇은 계약 | 모듈끼리 서로 알아야 하는 것을 최소로 줄이세요 | 결합도를 낮추세요 |
| blast radius | 블라스트 레디우스 | 여파가 미치는 범위 | 영향 범위 |
| fat model | 두꺼운 모델 | 기능이 과하게 몰려 있는 모델 | 책임이 과한 모델 |

## 쓰지 말 것과 쓸 것

아래는 자주 어긋나는 사례입니다. 목록에 없는 표현도 위의 다섯 순위로 판단하십시오.

### 용어 — 한국어 기술용어가 있는 경우

| 원어 | 쓰지 말 것 | 쓸 것 | 이유 |
|---|---|---|---|
| idempotent | 여러 번 해도 결과가 같은 | 멱등 | 멱등이 이미 표준어. 설명문으로 늘이면 문장이 무너진다. |
| invariant | 변하면 안 되는 규칙 | 불변식 (불변 조건) | 수학·설계 양쪽에서 통용되는 용어가 있다. |
| side effect | 부작용 | 부수 효과 | 부작용은 '해로운 결과'로 읽힌다. 함수형 문맥에서는 부수 효과. |
| immutable | 변경 못 하는 값 | 불변 (불변 객체) | 불변/가변이 짝으로 굳었다. |
| eventual consistency | 언젠가 같아지는 성질 | 최종 일관성 (최종적 일관성) | 클라우드 한국어 문서에서 굳은 표기다. |
| — | 결합도(coupling)를 낮추고 응집도(cohesion)를 높였습니다 | 결합도를 낮추고 응집도를 높였습니다 | 원어 병기는 문서에서 첫 등장 한 번만 합니다 |
| coupling | 서로 얽힌 정도 | 결합도 | 한자어 용어가 통용된다 |
| cohesion | 뭉쳐 있는 정도 | 응집도 | 한자어 용어가 통용된다 |
| side effect | 곁가지 효과 | 부수 효과 | 한자어 용어가 통용된다 |
| coupling | 붙어 있는 정도 | 결합도 | 국내 설계 문서의 표준 한자어. 풀어쓰면 길어진다. |
| cohesion | 뭉침 정도 | 응집도 | 결합도와 짝으로 쓰이는 굳은 한자어. |
| graceful shutdown | 우아한 종료 | 정상 종료 (안전 종료) | 쿠버네티스 한국어 문서도 '종료' 계열로 쓴다. '우아한'은 어색하다. |
| sharding | 조각 나눠 저장하기 | 샤딩 | 외래어가 표준으로 굳은 사례. 억지 한자어를 만들지 않는다. |
| circuit breaker | 회로 차단기 | 서킷 브레이커 | 직역하면 전기 부품이 된다. 패턴 이름은 음차. |
| garbage collection | 쓰레기 수집 | 가비지 컬렉션 (GC) | 직역은 청소 용역처럼 읽힌다. |
| memory leak | 메모리 새어 나감 | 메모리 누수 | 누수라는 한자어가 이미 표준이다. |
| regression | 퇴행 | 회귀 (회귀 버그, 회귀 테스트) | 회귀가 표준. 퇴행은 의학 용어로 읽힌다. |
| edge case | 가장자리 사례 | 엣지 케이스 (경계 조건) | 음차가 우세하고, 경계 조건도 자연스럽다. |
| sanitization | 소독 / 살균 | 정제 (입력값 정제, 이스케이프 처리) | 직역하면 위생 용어가 된다. |
| authentication | 본인 맞는지 확인하기 | 인증 | 인증 한 단어로 충분하다. |
| authorization | 허가 내주기 | 인가 / 권한 확인 | 인증(AuthN)과 인가(AuthZ)를 구분해야 한다. |
| observability | 관찰 가능도 | 관측 가능성 | 관측 가능성이 정착. 가시성(visibility)과는 다른 개념이다. |
| bottleneck | 목이 좁은 구간 | 병목 | 병목 두 글자가 표준이다. |
| fault tolerance | 장애 버티기 | 내결함성 | 내결함성이 굳은 한자어다. |
| dependency | 딸린 것 | 의존성 (패키지 문맥은 의존 패키지) | 의존성이 표준이다. |
| dependency injection | 의존 객체 넣어 주기 | 의존성 주입 | 프레임워크 문서의 정착 용어다. |
| separation of concerns | 신경 쓸 것 나누기 | 관심사의 분리 | 관심사라는 한자어가 이미 통용된다. |
| least privilege | 가장 적은 특권 | 최소 권한 (최소 권한 원칙) | 보안 문맥의 표준 용어다. |

### 은유 — 벗기고 개념의 이름을 쓸 것

| 원어 | 쓰지 말 것 | 쓸 것 | 이유 |
|---|---|---|---|
| heavy operation / lightweight library | 부담이 큰 연산 / 몸집이 작은 라이브러리 | 무거운 작업 / 가벼운 라이브러리 | 무게 은유는 정착했다. 풀어쓰면 오히려 어색하다. |
| thin contract | 얇은 계약 | 낮은 결합도 | thin과 contract를 둘 다 직역해 뜻이 사라졌다 |
| thin interface | 얇은 인터페이스 | 공개 범위가 좁은 인터페이스 | 인터페이스가 얇다는 말은 한국어에 없다 |
| keep it thin | 얇게 유지하다 | 최소한으로 유지하다 | 같은 은유의 서술형 |
| fat model | 두꺼운 모델 | 책임이 과한 모델 | fat은 두께가 아니라 책임 과다를 뜻한다 |
| hot path | 뜨거운 경로 | 핫 패스 | 온도 은유는 한국어로 옮기면 뜻이 사라진다. |
| stale data, stale cache | 신선하지 않은 데이터 / 김빠진 캐시 | 오래된 데이터 / 최신이 아닌 캐시 | 신선도 은유는 식품에만 쓴다. 최신 여부로 말한다. |

### 판교어와 한영 혼용

| 원어 | 쓰지 말 것 | 쓸 것 | 이유 |
|---|---|---|---|
| there is an issue | 이 부분에 이슈가 있습니다 | 이 부분에 문제가 있습니다 | 이슈는 이슈 트래커의 티켓을 뜻할 때만 남기고, 문제라는 뜻이면 문제로 쓴다. |
| check the logs | 로그를 체크했습니다 | 로그를 확인했습니다 | 확인이 표준이다. 다만 헬스 체크·체크박스·체크섬은 굳은 말이라 건드리지 않는다. |
| update the component's state | 이 컴포넌트의 state를 업데이트합니다 | 이 컴포넌트의 상태를 갱신합니다 | 식별자 이름이 아니라 개념을 가리키면 한국어 용어로 쓴다. |
| call this function | 이 function을 call합니다 | 이 함수를 호출합니다 | 함수·호출은 표준 한국어 용어가 있다. |
| deprecated | 이 API는 deprecated 됐습니다 | 이 API는 폐기 예정입니다 | 사용 중단·폐기 예정이 표준이고, 영어 서술어를 한국어 문장에 붙이지 않는다. |
| iterate over the array | array를 iterate합니다 | 배열을 순회합니다 | 배열·순회가 표준 용어다. |
| return a value | value를 리턴합니다 | 값을 반환합니다 | 값·반환이 표준 용어다. |

### 문장 구조

| 원어 | 쓰지 말 것 | 쓸 것 | 이유 |
|---|---|---|---|
| we | 우리는 ~합니다 | 주어를 빼고 대상을 주어로 놓습니다 | 영어의 인칭 주어를 직역했다. "우리는 캐시를 재생성한다"가 아니라 "캐시가 매번 새로 만들어집니다" |
| This change brings a performance improvement. | 이 변경은 성능 향상을 가져옵니다. | 이렇게 바꾸면 빨라집니다. | 무생물 주어가 무엇을 '가져오는' 구조는 영어식입니다. |
| I fixed the function that was causing slow responses because it rebuilt the cache on every call. | 호출마다 캐시를 새로 만들어서 응답을 느리게 만들고 있던 이 함수를 수정했습니다. | 이 함수가 호출마다 캐시를 새로 만들고 있었습니다. 그래서 응답이 느렸고, 지금은 고쳤습니다. | 영어 관계절을 명사 앞에 쌓지 말고 문장을 끊습니다. |
| This change removes the cache rebuild, which reduces latency, while all tests still pass and backward compatibility is preserved. | 이 변경은 캐시 재생성을 없애 지연 시간을 줄이면서, 동시에 모든 테스트를 통과하고 하위 호환도 유지합니다. | 캐시 재생성을 없애 지연 시간을 줄였습니다. 테스트는 전부 통과하고 하위 호환도 그대로입니다. | 영어 한 문장을 한국어 한 문장으로 옮기면 늘어집니다. 끊어 씁니다. |
| — | 한 문장에 절을 셋 이상 이어 붙이기 | 절 두 개까지. 50자를 넘으면 문장을 나눕니다 | 영어 한 문장을 한국어 한 문장으로 고집하면 늘어집니다 |

# 한국어 글 다듬기

출력 스타일이 **매 문장에** 적용하는 규칙은 분량 상한 때문에 50개 남짓입니다.
전체 규칙은 560개가 넘고 `rules/` 에 있습니다. 글을 검토하거나 고쳐 달라는 요청을 받으면
그 표를 열어 보십시오.

## 언제 이 스킬을 쓰나

- "이 문서 말투 좀 다듬어줘"
- "번역체 같은데 고쳐줘"
- "커밋 메시지 한국어로 자연스럽게 써줘"
- 한국어 README·API 문서·릴리스 노트를 쓰거나 고칠 때
- 용어를 통일해야 할 때

평소 대화에서는 이 스킬이 필요 없습니다. 출력 스타일이 이미 적용하고 있습니다.

## 먼저 이 다섯 순서로 판단합니다

1. **한국어 기술용어가 있으면 그것.** 대개 한자어입니다. 결합도, 의존성, 응집도, 불변식,
   멱등, 영향 범위, 책임, 경쟁 조건, 교착 상태, 처리량, 지연 시간, 부수 효과, 하위 호환.
2. **정착된 외래어가 있으면 그것.** 캐시, 커밋, 머지, 브랜치, 배포, 인터페이스, 리팩터링,
   스레드. 이런 말을 우리말로 바꾸지 마십시오.
3. **둘 다 없으면 원어를 그대로.**
4. **순우리말 풀어쓰기는 최후 수단입니다.** 서술문으로 늘이면 대개 더 어색해집니다.
   답이 길어지고 있으면 틀렸다고 의심하고 1번이나 2번을 다시 찾아보십시오.
5. **은유는 번역 대상이 아닙니다.** 활용형에도 똑같이 적용됩니다. "얇은 계약"만 피하는 것이
   아니라 "계약이 얇으면", "계약을 얇게", "계약이 두꺼워지는"도 모두 쓰지 않습니다.

4번이 가장 자주 어긋납니다. "자연스러운 한국어"는 순우리말을 뜻하지 않습니다.

## 규칙표

| 파일 | 다루는 것 |
|---|---|
| `rules/hanja.md` | 영어 개념에 대응하는 한국어 기술용어. 대개 한자어 |
| `rules/metaphors.md` | 영어 은유의 정착 여부 판정. 얇다·두껍다·깊다는 정착하지 않았다 |
| `rules/terms.md` | 직역 신조어와 불필요한 음차. 반대로 정착 외래어를 되돌리는 실수도 |
| `rules/patterns.md` | 번역체 문장 구조. 인칭 주어 직역, 기능동사 남용, 이중 피동 |
| `rules/pangyo.md` | 판교어와 한영 혼용 |
| `rules/register.md` | 어투 일관성, 사물 존대, 외래어 표기, 띄어쓰기 |
| `rules/observed.md` | 실제 출력에서 관찰한 실패. 짜낸 예시보다 값어치가 크다 |

표의 `검사` 칸이 그 규칙을 누가 막는지 알려 줍니다.

| 값 | 뜻 |
|---|---|
| `치환` | 린터가 자동으로 고칩니다 |
| `정규식` | 린터가 잡아서 알려 줍니다 |
| `프롬프트` | 문자열로 잡을 수 없습니다. 읽고 판단해야 합니다 |

`프롬프트` 규칙이 이 스킬의 값어치입니다. 문자열 검사로는 잡히지 않고 출력 스타일에도
분량 때문에 대부분 들어가지 못합니다. 글을 검토할 때 이 항목들을 직접 읽어 보십시오.

## 기계로 채점하기

규칙표를 눈으로 훑기 전에 린터를 돌리면 잡히는 것은 먼저 걸러집니다.

```bash
node scripts/score-response.mjs 문서.md          # 걸리는 표현을 나열한다
node scripts/score-response.mjs --fix 문서.md    # 치환 규칙을 적용한 결과를 내보낸다
node scripts/score-response.mjs --json 문서.md   # 기계가 읽을 형태
```

린터가 0건이라고 해서 자연스러운 글은 아닙니다. 문장 구조와 어투는 읽어야 압니다.

## 검사에서 빼기

문체 가이드처럼 나쁜 예를 일부러 인용하는 문서는 표시로 뺍니다.

```markdown
<!-- kimchi-ignore-file -->          문서 전체
<!-- kimchi-ignore-start --> … <!-- kimchi-ignore-end -->   구간
얇은 계약이라고 쓴 줄 <!-- kimchi-ignore -->   그 줄
```

## 자주 틀리는 것

- 순우리말로 풀어써서 더 어색하게 만들기 — "여파가 미치는 범위"보다 "영향 범위"
- 정착한 외래어를 되돌리기 — "캐시"를 "임시 저장소"로 바꾸는 것은 개선이 아니라 훼손
- 은유의 관형형만 고치고 활용형을 놓치기 — "얇은 계약"은 고치고 "계약이 얇으면"은 남기기
- 한자어 밀도를 올리다가 공문서체로 튀기 — "본 변경 사항은 상기 모듈에 대하여 적용됨"
- 사물 존대 — "빌드가 완료되셨습니다"
- 원어를 문장마다 병기하기 — 병기는 문서에서 첫 등장 한 번만
